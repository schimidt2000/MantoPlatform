# Contrato da API — 318

Envelope de erro = `json_error` (`docs/00` §5). Valores em string decimal ("2200.00"). Datas ISO em horário de parede
SP. Gates por função no início da view (Princípio XIII); módulo com comentário `RBAC:` no topo.

## `GET /api/pix` — `pix_read.py`

Gate: COMERCIAL, FINANCEIRO, SUPERADMIN (`_require_vendas`, molde `formularios_admin_read.py:34`).

Query: `aba` = `conferir` (default) | `ligados` (últimos 30 dias).

```json
{
  "itens": [{
    "id": 12, "valor": "2200.00", "pagador": "Nome", "conta": "Inter MEI", "recebido_em": "2026-10-22T10:10:34",
    "autenticado": true, "estado": "para_conferir", "tipo_sugestao": "venda",
    "sugestoes": [{"event_id": 1350, "titulo": "…", "data": "2026-12-12", "cliente": "…", "vendedor": "…",
                   "saldo": "2200.00", "motivos": ["valor = saldo", "nome bate"]}],
    "pagamento": null, "decidido_por": null, "motivo": "…"
  }],
  "contagem_conferir": 3,
  "flags": {"pode_desfazer": false, "pode_repasse": false, "pode_configurar": false}
}
```

Itens `tipo_sugestao='repasse_infinitepay'` só aparecem para FINANCEIRO/SUPERADMIN. `sugestoes` de repasse:
`[{"vendas": [{event_id, titulo, saldo}], "soma": "1000.00", "taxa": "50.00"}]`.

## `POST /api/pix/<id>/confirmar` — `pix_write.py`

Body: `{"event_id": 1350}` (venda) ou `{"event_ids": [..]}` (repasse). Gate: COMERCIAL, FINANCEIRO, SUPERADMIN; repasse
só FINANCEIRO, SUPERADMIN (403 para os demais). 200 `{"pix": {...}}`; 404 PIX inexistente; 409 `ja_decidido` (estado ≠
`para_conferir`), 409 `venda_indisponivel` (venda não é mais candidata: quitada/cancelada), 409 `cancelado` (núcleo).
"Outra venda…" usa o mesmo endpoint com um `event_id` fora das sugestões (deve ser venda aberta do universo).

## `POST /api/pix/<id>/descartar` — Body `{"event_id": 1350}`

Mesmo gate do confirmar. Tira a venda das sugestões; sem sugestões restantes → `sem_venda`. 200.

## `POST /api/pix/<id>/nao-e-venda` — mesmo gate. Estado → `sem_venda` (não reavalia mais). 200.

## `POST /api/pix/<id>/desfazer` — FINANCEIRO, SUPERADMIN (COMERCIAL → 403)

Pagamento sem arquivo de origem PIX → apagado (via núcleo `excluir`); com arquivo ou conciliado → `origem`
permanece, `pix` desvinculado (vira manual); repasse de várias vendas → o mesmo para cada pagamento de
`event_payment_id` + `pagamentos_extra`; PIX → `para_conferir` (candidatas recalculadas). 200; 409 se não está
ligado.

## `GET /api/pix/config` · `PATCH /api/pix/config` — SUPERADMIN

`{"ativo": false, "ativo_desde": null, "pagadores_proprios": ["Prime Dreams", …],
"contas": [{"id": 1, "apelido": "Inter MEI", "numero_conta": null, "ativa": true}]}`. PATCH aceita qualquer subconjunto;
ligar `ativo` grava `ativo_desde = agora`.

## `POST /api/events/<id>/payments` (existente, `agenda_write.py:2145`) — gate inalterado

Campos novos (multipart): `conta_id` (opcional), `anexar_a` (id de pagamento), `forcar_novo` ("1").

- Sem `anexar_a`/`forcar_novo` e existe no grupo pagamento `origem='pix_email'`, `file_path NULL`, mesmo valor →
  **409** `{"code": "possivel_duplicata", "pagamento": {"id", "valor", "conta", "recebido_em", "pagador"}}`.
- `anexar_a` → arquivo vai para o pagamento indicado (deve ser do grupo, origem PIX, sem arquivo; senão 400); recebido
  não muda.
- `forcar_novo` → fluxo de hoje.

## `GET /api/events/<id>` (existente) — `pagamentos.items[]` ganha

`"origem": "comprovante" | "pix_email"`, `"conta": "Inter MEI" | null`, `"pix": {"pagador", "recebido_em",
"automatico": bool, "decidido_por": str|null} | null`; `file_path` pode ser `null`.
