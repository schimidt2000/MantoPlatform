## Público (sem login)

### `POST /api/virtuais/pedidos/<public_token>/retorno` — novo

Chamado pela página do pedido ao voltar do checkout. Limite: 20/min por IP do cliente (R8).

Corpo (tudo opcional exceto `order_nsu`; strings até 120, `receipt_url` até 500):
```json
{ "order_nsu": "205-2-93c607ea49cd", "slug": "abc123", "transaction_nsu": "uuid",
  "capture_method": "pix", "receipt_url": "https://…" }
```
- `order_nsu` ≠ o do token → **404** `"Pedido não encontrado."` (nada gravado).
- Sem `slug`/`transaction_nsu` → **200** com o resumo atual (nada a provar).
- Com identificadores → reconsulta + `decidir_pagamento` → **200** com o resumo (igual ao
  `GET /api/virtuais/pedidos/<token>`), agora com `status` possivelmente `pago`/`cancelado`.
- Operadora travada/fora → **200** com o resumo. Os identificadores do retorno NÃO são gravados (só
  depois de provados); a página fica em "ainda não identificamos" e quem termina é o aviso ou a
  varredura — sem prova, o pedido vai para "a conferir" (`nao_sei`), nunca é dado como não pago.

### `GET /api/virtuais/pedidos/<public_token>` — alterado

Acrescenta `seconds_left` (int ≥ 0 ou `null`) e `confirming` (bool). Some `locked_until` cru?
**Não** — mantido por compatibilidade (o front antigo pode estar em cache); o front novo usa
`seconds_left`.

### `POST /api/virtuais/campanhas/<slug>/reservar` — alterado

- Resposta 201 acrescenta `seconds_left`.
- Horário a menos de 2 h → **409** `"Este horário fecha 2 horas antes. Escolha outro."`.
- Pagamento desligado/não configurado → **503** `"As reservas estão fechadas por enquanto."`
  (campanha publicada com interruptor desligado não deveria existir — FR-022 —, mas o caminho é
  coberto).
- Operadora recusou o link → **502** `"Não conseguimos abrir o pagamento. A equipe já foi avisada;
  tente de novo mais tarde ou fale com a gente no WhatsApp."` + `code` da operadora em `details`.
- Travado (local) → **502** `"Pagamento travado neste ambiente (cópia de teste)."`.

### `GET /api/virtuais/campanhas/<slug>/horarios` — alterado

Só horários que começam a mais de 2 h.

### `GET /api/virtuais/vitrine` — alterado

Só campanhas `listada=true`.

### `POST /api/webhooks/infinitepay/<token>` — alterado

- Token = atual ou anterior dentro de 24 h (`compare_digest`) → grava `pendente`, dispara a thread,
  **200** `{"success": true, "message": null}` em < 100 ms.
- Token inválido → **404**; grava resumo de 2 KB com `transaction_nsu = NULL`.
- Corpo > 64 KB → **413** antes do parse. Limite 60/min por IP.

## Operadora (InfinitePay) — contrato real, provado em 20/10/2026

`POST https://api.checkout.infinitepay.io/links` — `handle`, `order_nsu`, `redirect_url`,
`webhook_url`, `items[{quantity, price (centavos), description}]`, `customer{email, phone_number
(só dígitos)}`; resposta `{"url": …}`. Com `INFINITEPAY_API_KEY`: header `X-Api-Key` +
`options{valid_until, single_payment}`.

`POST https://api.checkout.infinitepay.io/payment_check` — `{handle, order_nsu, transaction_nsu,
slug}`; pago → `{success:true, paid:true, amount, paid_amount, installments, capture_method}`; só
`handle+order_nsu` (ou não encontrado) → `200 {"success":false}`.

Aviso: `{amount, capture_method, installments, invoice_slug, items, order_nsu, paid_amount,
receipt_url, transaction_nsu}` (centavos; sem `paid`).

Retorno: `redirect_url?receipt_url=…&order_nsu=…&slug=…&capture_method=…&transaction_nsu=…`.
